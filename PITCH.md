# Demo script

## 90-second version

**0–10 seconds — problem**

“[User] loses [time/money/trust] because [messy input] has to be turned into [decision/action] manually.”

**10–20 seconds — promise**

“We built [product]: it turns [input] into [specific outcome], while keeping the evidence visible and the human in control.”

**20–60 seconds — live proof**

1. Start from the reset state.
2. Add the pre-tested synthetic input.
3. Point out the extracted evidence—not implementation details.
4. Show the proposed action.
5. Approve it and reveal the durable result/audit trail.

**60–75 seconds — why this stack**

“OpenAI handles [specific intelligence]. Cala provides [specific data-layer value]. Entire preserves the build decisions and checkpoints. [Optional partner] is used for [specific necessary capability].”

**75–90 seconds — impact**

“This changes [old workflow] from [old cost/risk] to [measurable better state]. The next step is [one credible extension].”

## Demo rules

- Never begin with the architecture diagram.
- Do not type a long prompt live.
- Use one pre-tested input and one visible result.
- Name synthetic or mocked behavior honestly.
- Keep the cursor away from secrets, terminals with history, and notification popups.
- Finish on the outcome screen, not the code editor.

## If the live provider fails

“The provider is slow, so I’m switching to the deterministic demo fixture generated by the same response schema. The product flow and validation are identical.”

Then continue immediately. Do not debug on stage.

## Matchmaking introduction

“I’m Yazide. I build operational AI products end to end. I’m aiming for one polished, traceable workflow we can demo reliably tonight. I can own product and full-stack implementation; I’m looking for someone strong in [design/data/domain] who wants a tight scope and a working lunch milestone.”
